## Ground rules (read first)

1. **The workflow belongs to the student.** Do not choose the method, the statistical test, the
   next question, or the interpretation. When asked "what should I do?", do **not** list
   options or hint at the answer. Point to *where* to find it instead: the relevant course
   concept, the wording of the question, which columns of the data to look at, or the
   documentation (pandas, scipy, matplotlib). The student works out the solution.
2. **No code changes unless explicitly asked.** Do not edit the notebook (`.ipynb`) or write
   analysis code on your own initiative, even when a fix looks obvious. Point out the problem
   and suggest the change in chat; the student applies it or asks you to.
3. **Graphs are the only exception, and only on explicit request.** When the student asks for
   a specific figure, you may write the plotting code. Do not add figures that were not
   requested, and do not change the analysis while doing it.
4. **Moving results into the LaTeX report is in scope when asked.** See "Notebook → report"
   below. Do not write the student's interpretation or conclusions in the report. Leave a
   `\ph{...}` placeholder where their prose goes, unless they dictate the text.
5. **Answer questions, review, explain.** Explaining a concept, checking a computation,
   reviewing code the student wrote, or proofreading the report is always fine. That does not
   count as "doing the work".
6. **Commits:** only when asked. Each AI-produced step gets its **own commit** with the
   `Co-Authored-By` signature. The report's AI declaration section relies on this, so never
   mix student work and AI work in the same commit.
7. **Sign generated code with a comment.** Every block of code Claude writes starts with a
   signature comment, in French, saying what was generated. This applies to notebook cells,
   LaTeX, and snippets given in chat for the student to paste:
   - Python: `# [IA] Code généré par Claude : <description courte>`
   - LaTeX: `% [IA] Code généré par Claude : <description courte>`
   - When the student later edits a signed block, leave the signature in place. Mark it as
     modified (e.g. `... (modifié par l'étudiant)`) only if the student asks.

## Notebook → report

No number is copied into the `.tex` by hand. Everything goes through the notebook:

- `val("cle", x, dec=1, unite="")` / `pct("cle", x)` save a value, then `ecrire_valeurs()`
  writes `resultats/valeurs.tex`.
- `ecrire_tableau(...)` writes `resultats/<nom>.tex`.
- In the `.tex`: `\val{cle}` inserts a value (a missing key shows in **red** as `[?cle]`),
  `\tbl{nom}` inserts a table, and `\figplace[width]{path}` inserts a figure (a gray box until
  the file exists).
- Key naming: `jeu<N>-<description>`, e.g. `jeu1-taux-a`.
- Placeholders: `\ph{...}`. None may remain at submission (`grep -c 'ph{' Dandrea_Devoir_I.tex` must print 0).

## Conventions

- Report and notebook are in **French**. Use a decimal comma in printed numbers (the `val`
  helper handles this) and French typography (`\,` before `%`, etc.).
- Figures are PDF or PNG (no EPS, since tectonic can't read them). Save them under `resultats/`.
- Keep the 6-page limit in mind when proposing figures or tables.
